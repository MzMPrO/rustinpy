Работаем по скиллу spec-first (роль Строитель, без архитектора): интервью и ТЗ проекта прямо в Claude Code. **Код не пишем.**
Если у пользователя есть claude.ai Project с архитектором, лучше делать ТЗ там и прийти сюда с KICKOFF.md — скажи об этом одной строкой.

Идея от пользователя (может быть пустой): $ARGUMENTS

1. Прочитай `docs/SPEC.md`, `docs/DECISIONS.md` и хвост `docs/PROGRESS.md`. Если в проекте уже есть код, изучи его и заполни всё, что видно из кода (режим внедрения).
2. Если есть скилл spec-first, прочитай его `references/interview.md` и возьми из него категории и вопросы под стек проекта.
3. Задай **одну пачку из 5–10 пронумерованных вопросов**. У каждого — вариант по умолчанию в [скобках] и полстроки о том, зачем он нужен. Начинай с того, что влияет на архитектуру.
4. После ответа сразу обнови `docs/SPEC.md` (статус остаётся ЧЕРНОВИК), затем задай следующую пачку. Указывай на противоречия между ответами.
5. Когда каждая категория закрыта (ответ / «не нужно» / допущение), а «Открытые вопросы» пусты:
   - заполни «Структуру проекта», «Стратегию тестирования», «Критерии готовности» (`AC-01…`, `(ручная)`) и «План реализации» (этап 0 — инфраструктура);
   - покажи резюме: цель, объём MVP, ключевые решения, **все допущения**;
   - попроси прочитать `docs/SPEC.md` и ответить **«утверждаю»**.
6. Статус УТВЕРЖДЕНО сам не ставь — его выставит хук по слову пользователя.
