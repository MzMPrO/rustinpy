## D-001 · 2026-10-17 · Работаем по spec-first
- **Контекст:** в прошлых проектах сессии забывались, код начинался до выяснения деталей, структура расползалась
- **Решение:** ТЗ и спеки фич до кода, утверждение словом «утверждаю», журнал в docs/, хуки-шлюз
- **Почему:** решения должен принимать человек, а контекст — жить в файлах, а не в памяти сессии
- **Альтернативы:** только инструкции в CLAUDE.md — отвергнуто, потому что это совет, а не запрет
- **Последствия:** любая работа вне утверждённой спеки начинается с `/feature`

## D-002 · 2026-10-17 · Реестр @algo без обёртки + выгрузка через AST
- **Контекст:** `show`/`export` должны отдавать самодостаточный код, а doctest и `inspect` — работать как обычно
- **Решение:** `@algo` только регистрирует объект и возвращает его без изменений; исходник берётся через `ast` модуля: сам объект + транзитивные `requires` + только те импорты stdlib, имена которых встречаются в коде; декоратор `@algo` вырезается
- **Почему:** нет накладных расходов на вызов, нет проблем с doctest; самодостаточность проверяется автоматически (AC-07: выгруженный код выполняется без пакета и проходит свой doctest)
- **Альтернативы:** хранить исходники отдельно в .txt — отвергнуто (рассинхрон с кодом)
- **Последствия:** зависимости внутри модуля (константы, вспомогалки, другие алгоритмы) обязательно перечислять в `requires`, иначе AC-07 падает

## D-003 · 2026-10-17 · mypy проверяет под Python 3.10, совместимость с 3.9 — тестами
- **Контекст:** mypy 2.4 не поддерживает `python_version = 3.9` (минимум 3.10)
- **Решение:** `python_version = "3.10"` в mypy; запуск всех тестов на настоящем 3.9 (CI + локально через uv); мета-тест `test_ac_14` запрещает API, которых нет в 3.9 (`int.bit_count`, `pairwise`, `zip(strict=)`, `match`, `bisect(key=)`), и требует `from __future__ import annotations` в каждом файле
- **Почему:** старый mypy ради цели 3.9 пришлось бы закрепить на устаревшей версии
- **Альтернативы:** mypy 1.x с целью 3.9 — отвергнуто (устаревший инструмент, другая строгость)
- **Последствия:** ошибки типа «функции нет в 3.9» ловят тесты на 3.9 и `test_ac_14`, а не mypy

## D-004 · 2026-10-17 · Версии ruff и mypy закреплены, кириллица разрешена
- **Контекст:** форматирование ruff меняется между версиями; правила RUF001–003 считают кириллицу «похожими символами»
- **Решение:** `ruff==0.17.1`, `mypy==2.4.0` в extras `dev`, тот же `rev` у ruff в pre-commit; RUF001–003 и E741 выключены; `docs/` исключён из ruff (ruff 0.17 переформатирует Python-блоки в Markdown, а `docs/handoff` хранится дословно)
- **Почему:** CI и локальная машина должны форматировать одинаково
- **Последствия:** обновление ruff — отдельный коммит с `ruff format .`

## D-005 · 2026-10-17 · Исходники только в символах cp1251
- **Контекст:** `rustinpy show` печатает исходник в консоль; в русской Windows это cp1251, и символы вроде `→`, `≤`, `φ` роняют вывод
- **Решение:** в `src/` допускаются только символы, которые есть в cp1251 (ASCII + кириллица + `—`, `№`); тест `test_ac_09_sources_are_printable_on_windows_console`; CLI в pipe и файл пишет UTF-8
- **Последствия:** в докстрингах пишем `->`, `<=`, `phi`, `mu` вместо `→`, `≤`, `φ`, `μ`

## D-006 · 2026-10-17 · Задачи ICPC-UZ без условия — заглушки до этапа 5
- **Контекст:** условий ICPC-UZ 2023–2025 в задании нет (Q-1: ищу сам на этапе 5)
- **Решение:** если по описанию из задания алгоритм однозначен (например, Du's sieve для суммы phi), он реализован и проверен перебором, но помечен `verified=False`; если описание неоднозначно, это `stub=True` с идеей в `Idea:`
- **Почему:** не выдумывать решения (требование задания, раздел 5.14)
- **Последствия:** всё такое перечислено в docs/PROGRESS.md, раздел NOT VERIFIED; на этапе 5 заглушки заменяются реализациями после сверки условий
